# 做绘本的经验（2026-09）

写给以后接手的人（或以后的 Claude）：动手做新书之前先读这份。流程和命令见 [HANDBOOK.md](HANDBOOK.md)。

## 现在的状态（2026-09-23）

- 14 本书（最早 5 本 + 搞笑系列 9 本），中文、英文两版都已做完、发布；印刷文件在 `out/print_<slug>[_en]/`。

## 家长在意什么（按重要程度）

1. **故事比画重要。** 搞笑系列第一版画得不错，但家长说「硬、没有故事感」：9 本都套同一个模板（嘿小朋友 → 一串冷知识 → 千万别… → 那天你… → 现在你知道了 + 一串规矩）。改好的写法：
   - 主角有想要的东西、有担心的事；
   - 每一页都是上一页引出来的；
   - 前面警告的那件事后面真的发生；
   - 有一句反复出现的话；
   - 结尾不讲道理。
   - 家长最后用别的 AI 改了全部文字，再自己合并。下次先给故事大纲和文字，让家长改定了**再**出图。
2. **图要孩子友好：** 一眼看得懂、主角大、一页一件事；不要尖牙、怒脸、吓人的大特写、大头娃娃。审图时「不好读」「不友好」都算硬伤，要重画。
3. **少而好。** 家长一次删掉了 115 本旧书，理由是「太难看了」。
4. **跟孩子有关的决定是家长的。** 行为书都来自真实的事，怎么教、用什么词要问家长（例如用「下次可以说出来」、不说「告状」）。犯错的角色用恐龙或龙，不用孩子本人。
5. **朗读体：** 孩子只看图，家长念字，所以字要够多（中文约 700 字/本），而且只写画面里已经有的东西；不要知识卡。

## 流程里好用的做法

- 全部文字放在一个 md 里（页码 | 画面上有什么 | 旁白），这是交给家长或别的 AI 改稿的格式（`drafts/story_scripts_for_review.md`，由 `tools/make_review_md.py` 生成）。
- 改定的文字用脚本写回（`apply_final_text.py`），别手抄。
- 重画前先并行派审稿 agent（每个 3 本），逐页对照「字说的」和「图画的」；然后出图 → 自己逐页看 → 重试 → 打包 → 再并行审一遍 → 发布。
- 有孩子真人的页（早期几本）用 `fix_edit.py` 局部改，不整页重画，这样脸和画风都能保住。
- **三次原则：** 同一页模型错三次就别再改提示词了，改成裁图、局部改（fix_edit），或者改文字去配图。

## Qwen-Image 反复出的毛病

总规律：**提示词里出现的名词都会被画出来**，否定句也一样。

- 画风那句话只写媒介和纸（线条、平涂、纸纹），不写角色、不写否定、不写能被当成东西的颜色名（"brick red" 画出了砖头）。
- 角色放进 cast，只在需要它的那一页引用，并写明几只（"only one dragon in the picture"）。
- 同一个角色占位符在一页里出现两次，就画出两只；第二次提到时改成 "the triceratops"。
- 比较对象会被画出来："half the size of a grown-up T. rex" 多出一只大霸王龙，"no bigger than a cat" 画出了猫。大小用 "short and chubby" 这类不带比较对象的词写。
- "no sharp teeth" 照样出尖牙，要写正面的样子："soft rounded, friendly"。
- 凶脸通常是场景词招来的（annoyed、mouth wide open），要改场景词：嘴写 "a small round O shape"，惊吓写 "eyes squeezed shut"。
- 孩子要写死外形和衣服（"little boy with a short black buzz cut, wearing a red t-shirt and blue shorts"），不然每页都不一样，还常被画成女孩。
- 爱加画框：出完量边、裁掉（`tools/frames.py`），比重画省事。自动检测会把贴边的草地、树干当成框，要按页确认。
- 同一句描述加同一个 seed 重出，基本还是同一张构图；要换构图就给这一页单独设 `"seed"`。
- 双脖子的长颈龙、「抱着一颗头」这类怪图：改用 fix_edit 局部修，或者改场景。

## 印刷排版（make_print.py）

- 字放在「不是纸色的像素」最少的地方，不按梯度找：平涂的大脸梯度很低，按梯度找字会放到脸上。
- 字块试三种宽度，好塞进空角。
- 英文按单词折行，标点不放行首。
- 画面没留空的书（早期 5 本）用图上、字下的排法（band_page）。

## 运维上的坑（Windows 这台机器）

- Git Bash 里的 `python` 是 3.4，一律用 `venv/python.exe`，并设 `PYTHONIOENCODING=utf-8`。
- 用 printf 或 heredoc 写 .bat、.py 会吃掉 `\b` 和 `\n`，要用编辑器或写文件的工具。
- 内存紧的时候（编辑模型加打包同时跑）后台任务会被系统杀掉。重的打包放前台、一次一本。
- ComfyUI 可能跑到一半挂掉（`WinError 10061`）：重启 ComfyUI，把没出完的页重新排队。
- 提交的文档里不能出现孩子照片的文件名（写成 `<照片1>`），也不能出现发布链接；照片和生成的图都在 .gitignore 里。

## tools/ 里的小工具

从 `storybook/` 目录用 `..\venv\python.exe tools\<脚本>` 运行：

| 脚本 | 用途 |
|---|---|
| `frames.py` | 量 bakeoff 页四边的画框（`m slug_pNN`），按像素裁掉（`c slug_pNN=px`），原图备份到 `_old/` |
| `unframe.py` | 自动找画框再裁（只当参考，要人工确认） |
| `crop.py` | 按比例裁几块图拼在一起，用来放大看细节 |
| `sheet.py` / `review_sheet.py` | 审图联系表（图 + 旁白），输出到 `out/_review/` |
| `en_build.py` | 英文版网页和印刷 PDF（用中文版的图） |
| `early_build.py` | 早期 5 本的中英文网页和印刷文件（图在 `out/<image_dir>`） |
| `make_review_md.py` | 生成给家长或别的 AI 改稿用的剧本 md |

`drafts/new_book_ideas.md` 是还没做的书的点子，`drafts/workflow_for_friend.md` 是写给朋友的整套流程说明。
