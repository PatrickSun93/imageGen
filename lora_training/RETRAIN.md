# 补照片后重新训练 — 操作流程

下次发照片时直接说"练 v3"，我按这个流程走。

## 一、什么样的照片有用

**最缺的（优先补）**：

- **不同衣服**：现在条纹衫已占 42%，同一件衣服别再多了
- **不同场景**：户外、公园、餐厅、车里、洗澡后 —— 家里已经够多
- **不同光线**：白天窗边、傍晚、灯光下
- **侧脸**：正左 / 正右的纯侧面，现在几乎没有

**别再发的**：

- 同一天同一件衣服连拍多张（信息量重复）
- 脸小于画面 1/4 的远景
- 脸被帽子/玩具/食物挡住的
- 画面里有别人的

**5 张不同场景 > 20 张同一天连拍。**

## 二、我会做的

1. 从上传目录直接取图（你不用手动复制到任何地方）
2. 逐张写标注 —— 只写**可变因素**（衣服、场景、姿势、表情、视角），
   绝不写长相特征，那些要留给触发词 `ohwx boy` 独占
3. 检查衣服/场景分布，**任何单一元素超过 45% 就报警**
4. 剔掉不合格的，告诉你剔了哪些、为什么
5. 起训，中途每 400 步存档
6. 练完和上一版**同种子 A/B 对比**，确认真的更好才换上

### 标注长什么样

素材图片和标注都**不在版本库里**（私人照片）。格式：每张图配一个同名 `.txt`，
单行，逗号分隔。下面是虚构示例：

```
ohwx boy, wearing a red hoodie, sitting on a park bench, side view,
upper body, looking up, autumn trees behind, outdoors
```

```
ohwx boy, wearing a yellow raincoat, standing in a puddle, full body,
front view, mouth open laughing, rainy street behind
```

三条规矩：

- **开头永远是触发词 `ohwx boy`**。`dataset_config.toml` 里 `keep_tokens = 2`
  就是为了保证这两个 token 不被 shuffle 打乱。
- 后面只写**可变因素**，顺序：衣服 → 场景 → 构图/视角 → 表情 → 背景。
- **绝不写长相**（发型、眼睛、脸型、肤色）。写了等于告诉模型这些是可变属性，
  身份就学不进触发词里——这是最容易犯、也最难查的错。

## 三、参数怎么随素材调整

| 素材张数 | num_repeats | max_train_steps |
|---|---|---|
| 10~15 | 10 | 1200 |
| 16~25 | 8 | 1500 |
| 26~40 | 6 | 1800 |

原则：`张数 × repeats` 保持在 150 上下，步数随素材量小幅增加。
改这两个值：`dataset_config.toml` 的 `num_repeats`、`train.sh` 的 `--max_train_steps`。

## 四、版本管理

```
lora_training/
  raw/              素材 + 标注（累积，不删）
  output_v1/        v1 存档（11 张 / 1200 步）
  output/           当前训练版本的存档
  train.sh          训练脚本，改 --output_name 换版本号
  train_v2.log      训练日志
```

**旧版别删**。新版不一定更好——步数多了会过拟合（脸变僵、表情单一），
素材偏了会污染（比如穿什么都自动长出条纹衫）。留着才能对比回退。

## 五、练完必做的三个检查

用 `bench/compare_lora.sh`：

1. **同种子 A/B**：新旧版跑同一场景同一种子，直接看哪个更像
2. **挑存档**：400/800/1200/1500 都试，**不一定最后一个最好**
3. **污染检查**：让他穿红雨衣站在雨里，看会不会自动长出条纹衫
